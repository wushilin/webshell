# Mobile UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the webshell terminal usable on phones: soft-key bar with sticky Ctrl, one-line top bar with a `⋯` menu, keyboard-aware layout via visualViewport, and instant reconnect on returning to the tab.

**Architecture:** All changes live in `static/terminal.html` (inline CSS + JS; the Rust server embeds it via `include_str!` and needs no changes). The key bar and pane area are positioned from the *visual* viewport so they stay above the iOS soft keyboard; top-bar controls are physically re-slotted between the inline bar and a popover on breakpoint changes so existing event listeners keep working.

**Tech Stack:** Vanilla JS, xterm.js 5.5 (already loaded), visualViewport API, matchMedia.

**Spec:** `docs/superpowers/specs/2026-07-31-mobile-ux-design.md`

## Global Constraints

- Single file: only `static/terminal.html` changes (plus this plan/spec). No server or protocol changes.
- Primary target iPhone Chrome (WebKit); Android Chrome and desktop must not regress.
- Key bar keys, exactly: `esc` `tab` `ctrl` `↑` `↓` `←` `→` `|` `-`. Touch devices only (`pointer: coarse`).
- Ctrl is one-shot sticky; multi-character input chunks disarm it and pass unmodified.
- Compact-bar breakpoint: `max-width: 640px`. Collapsed bar shows only slots, status, `⋯`.
- The `@media (max-width: 640px) { #panes { top: 76px; } }` hack must be gone by the end.
- Where `visualViewport` is unavailable, behavior degrades to the current `window.resize` handling.
- No test framework exists. Every task's test cycle is: extract inline script → `node --check`, plus concrete manual checks listed in Task 5. Syntax check command (from repo root):

```js
    // ---- compact top bar: on narrow screens the right-side controls live
    // in the ⋯ popover; on wide screens they sit inline. The elements are
    // moved, not cloned, so their listeners survive the transition. ----
    const barEl = document.getElementById("bar");
    const moreBtn = document.getElementById("more");
    const morePanel = document.getElementById("morePanel");
    const growEl = document.getElementById("grow");
    const roLabel = document.getElementById("roLabel");
    const shareBtn = document.getElementById("share");
    const resetBtn = document.getElementById("reset");
    const cogBtn = document.getElementById("cog");
    const logoutForm = document.getElementById("logoutForm");
    const narrow = window.matchMedia("(max-width: 640px)");

    function layoutBar() {
      if (narrow.matches) {
        [roLabel, shareBtn, resetBtn, cogBtn, logoutForm].forEach((el) => morePanel.appendChild(el));
      } else {
        morePanel.hidden = true;
        [roLabel, shareBtn, resetBtn].forEach((el) => barEl.insertBefore(el, growEl));
        barEl.appendChild(cogBtn);
        barEl.appendChild(logoutForm);
      }
      panesEl.style.top = barEl.offsetHeight + "px";
    }
    moreBtn.addEventListener("click", (e) => { e.stopPropagation(); morePanel.hidden = !morePanel.hidden; });
    document.addEventListener("click", (e) => {
      if (!morePanel.hidden && !morePanel.contains(e.target) && e.target !== moreBtn) morePanel.hidden = true;
    });
    // Opening display settings from inside the menu: close the menu so the
    // two popovers don't stack in the same corner.
    cogBtn.addEventListener("click", () => { morePanel.hidden = true; });
    narrow.addEventListener("change", layoutBar);
    layoutBar();
```

- [ ] **Step 3: Build the key bar**

Insert after Task 1's `layoutBar();` line:

```js
    // ---- mobile key bar (touch devices only) ----
    const keyBar = document.getElementById("keybar");
    let ctrlArmed = false;
    let ctrlBtn = null;

    function setCtrl(on) {
      ctrlArmed = on;
      if (ctrlBtn) ctrlBtn.classList.toggle("armed", on);
    }
    // Map a keystroke to its control byte: letters and @[\]^_ use code&31,
    // ? maps to DEL; anything else passes through unchanged.
    function ctrlTransform(d) {
      if (d === "?") return "\x7f";
      const code = d.toUpperCase().charCodeAt(0);
      if (code >= 64 && code <= 95) return String.fromCharCode(code & 31);
      return d;
    }
    const KEYS = [
      ["esc", "\x1b"], ["tab", "\t"], ["ctrl", null],
      ["↑", "\x1b[A"], ["↓", "\x1b[B"], ["←", "\x1b[D"], ["→", "\x1b[C"],
      ["|", "|"], ["-", "-"],
    ];
    KEYS.forEach(([label, seq]) => {
      const b = document.createElement("button");
      b.textContent = label;
      // pointerdown + preventDefault: never move focus, so the soft
      // keyboard stays up while tapping bar keys.
      b.addEventListener("pointerdown", (e) => {
        e.preventDefault();
        if (seq === null) { setCtrl(!ctrlArmed); return; }
        const s = sessions[active];
        if (s) s.input(seq);
      });
      if (seq === null) ctrlBtn = b;
      keyBar.appendChild(b);
    });
    if (window.matchMedia("(pointer: coarse)").matches) {
      keyBar.hidden = false;
      panesEl.style.bottom = keyBar.offsetHeight + "px";
    }
```

(The `panesEl.style.bottom` line is transitional; Task 3 replaces it with the full viewport layout.)

### Task 3: Keyboard-aware layout via visualViewport

**Files:**
- Modify: `static/terminal.html` (JS: the `window.addEventListener("resize", …)` block ~line 512, plus the end of Task 2's key bar block)

**Interfaces:**
- Consumes: `barEl` (Task 1), `keyBar` (Task 2), `sessions`, `active`, `panesEl`.
- Produces: `scheduleLayout()` — coalesced relayout, the only resize entry point afterward.

- [ ] **Step 1: Replace the resize handler with viewport-driven layout**

Replace this block:

```js
    // Only the active pane can be measured; resize it on viewport changes.
    window.addEventListener("resize", () => {
      const s = sessions[active];
      if (s) s.fitAndResize();
    });
```

with:

```js
    // ---- keyboard-aware layout: size everything to the *visible* viewport.
    // iOS WebKit does not shrink the layout viewport for the soft keyboard —
    // it scrolls the page instead. Pin the scroll and derive the occluded
    // height from visualViewport, so the key bar rides on top of the
    // keyboard and the terminal fits in what remains. ----
    let layoutQueued = false;
    function layoutViewport() {
      layoutQueued = false;
      const vv = window.visualViewport;
      let occluded = 0;
      if (vv) {
        if (window.scrollY) window.scrollTo(0, 0);
        occluded = Math.max(0, window.innerHeight - vv.height - vv.offsetTop);
      }
      const kb = keyBar.hidden ? 0 : keyBar.offsetHeight;
      keyBar.style.bottom = occluded + "px";
      panesEl.style.top = barEl.offsetHeight + "px";
      panesEl.style.bottom = (occluded + kb) + "px";
      const s = sessions[active];
      if (s) s.fitAndResize();
    }
    function scheduleLayout() {
      if (layoutQueued) return;
      layoutQueued = true;
      requestAnimationFrame(layoutViewport);
    }
    if (window.visualViewport) {
      window.visualViewport.addEventListener("resize", scheduleLayout);
      window.visualViewport.addEventListener("scroll", scheduleLayout);
    }
    window.addEventListener("resize", scheduleLayout);
    scheduleLayout();
```

### Task 4: Foreground fast-reconnect

**Files:**
- Modify: `static/terminal.html` (JS, after the `setInterval(refreshSlots, 5000);` line)

**Interfaces:**
- Consumes: `sessions`, `Session.prototype.reconnect()`, `Session.reconnectDelay`, `refreshSlots()` (all existing).

- [ ] **Step 1: Add the visibilitychange handler**

Insert after `setInterval(refreshSlots, 5000);`:

```js
    // Coming back to the foreground (mobile backgrounds kill sockets):
    // reconnect dead sessions immediately instead of waiting out the
    // exponential backoff, which can sit at 10s.
    document.addEventListener("visibilitychange", () => {
      if (document.visibilityState !== "visible") return;
      sessions.forEach((s) => {
        if (!s || !s.opened) return;
        if (!s.ws || s.ws.readyState === WebSocket.CLOSING || s.ws.readyState === WebSocket.CLOSED) {
          s.reconnectDelay = 500;
          s.reconnect();
        }
      });
      refreshSlots();
    });
```
